# 07 i18n

## Provider API Shape

i18n is standardized on an in-house implementation (`src/i18n/`). No external library is used.

- `I18nProvider` provides `{ lang, setLang, t }`
- `t(key, params?)` supports placeholder interpolation in the `{name}` format
- Export `LANGUAGES: { id: Lang; label: string }[]`, which the language Select on the settings screen references
- Persist the language to `localStorage` (key: `<app>.lang`) and reflect it in `document.documentElement.lang`
- The Japanese catalog (`locales/ja.ts`) is the source of truth, and other languages are forced into the same shape with `Record<TranslationKey, string>`

## Key Naming Conventions

Name keys in two levels: `<domain>.<name>`. The shared domains are as follows.

| Domain | Purpose | Examples |
| --- | --- | --- |
| `common.*` | Generic buttons and actions | `common.close`, `common.delete` |
| `app.*` | App name and global strings | `app.title`, `app.newSession` |
| `settings.*` | Settings screen sections | `settings.language`, `settings.theme`, `settings.about` |
| `about.*` | About section | `about.version`, `about.ossTitle`, `about.license` |

- A description is the label key + the `Desc` suffix (e.g. `settings.languageDesc`)
- App-specific screens get their own consistent domains (meguri: `home.*` / `workspace.*`)

## Shared Strings

Translations for the shared `settings.*` / `about.*` keys are kept identical across apps (only the app name part is replaced). Example: `settings.about` = 「このアプリについて」 / "About".
